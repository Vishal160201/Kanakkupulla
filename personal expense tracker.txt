SCHEMA — prisma/schema.prisma

model PersonalExpense {
  id String @id @default(cuid())
  title String
  amount Float
  type String // CREDIT/DEBIT
  category String
  date DateTime
  paymentSource String
  isEMI Boolean @default(false)
  emiId String?
  notes String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?
  emi PersonalEMI? @relation(fields: [emiId], references: [id])
  @@index([date]) @@index([type]) @@index([deletedAt])
}

model PersonalEMI {
  id String @id @default(cuid())
  title String
  totalAmount Float
  emiAmount Float
  totalMonths Int
  paidMonths Int @default(0)
  startDate DateTime
  nextDueDate DateTime
  cardId String?
  status String @default("ACTIVE") // ACTIVE/COMPLETED/PAUSED
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  expenses PersonalExpense[]
  @@index([status]) @@index([nextDueDate])
}

model PersonalCard {
  id String @id @default(cuid())
  name String
  type String // CREDIT/DEBIT
  lastFour String
  bank String
  billingDate Int?
  dueDate Int?
  creditLimit Float?
  color String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

CONSTRAINTS
- No native <select>, <input type="date">, <input type="color">, alert(), confirm() anywhere.
- All custom: CustomDropdown, CustomMultiDropdown, custom date picker, inline confirmations.
- Email guard at: middleware (proxy.ts), every /api/personal/* handler, nav tab render, recycle bin personal tab render.
- Soft-delete pattern (deletedAt) for PersonalExpense. Hard-delete for PersonalCard.
- SWR for all data fetching. mutate() after every create/edit/delete — no router.refresh().
